## 3. The incident (read this one)

While verifying S141-04's Apples hookup live (the whole point was to prove it end-to-end, not
just unit-test it), `emily apples post` failed with "IDUNA_AGENT_SECRET not set." Root cause:
`cmd/bootstrap`'s `writeSecretsEnv` overwrote `var/agent-secrets.env` with *only* the current
run's newly-provisioned secrets instead of merging with what was already there. Because this run
provisioned 4 new agents (NORN + the 3 backlogged-since-creation ones above), it silently
destroyed the plaintext for EMILY-PRIME, FATBABY-EMILY, EMIREE, JON, BOB, and TYLER. Their
database `api_key_hash` was untouched — nothing was actually broken for already-running
processes — but the plaintext was gone from the only place it's ever written (git-ignored, no
backup, by design).

**Recovery:** EMILY-PRIME's plaintext was recoverable verbatim from a live `emily-agent` process's
environment (`/proc/<pid>/environ`). The other five were not recoverable anywhere (confirmed via a
repo-wide grep and a full `/proc` scan of every fatbaby-owned process) and were deliberately
rotated — cleared their `api_key_hash` in the database, re-ran bootstrap to regenerate fresh
secrets for exactly those five. **All ten agents verified live post-recovery** — every one
authenticates successfully against the running IDUNA instance, checked twice (once mid-recovery,
once definitively afterward after catching a stale-shell-env-var scare that turned out to be
nothing — the file and DB were consistent throughout).

**Fixed at the root:** `writeSecretsEnv` now merges with existing file content instead of
overwriting, with 6 regression tests including one that names the exact bug. Also found and fixed
a related `.gitignore` bug while committing the test: a bare `bootstrap` pattern (meant only for
the compiled binary at repo root) was shadowing the entire `cmd/bootstrap/` source directory,
silently hiding new files there from git — this could have hidden the regression test itself.

**Apple #9930** (escalation type, full writeup) is the durable record of this. No external
exposure — these are M2M service credentials between components on the same machine, never
transmitted anywhere except at point of use.
