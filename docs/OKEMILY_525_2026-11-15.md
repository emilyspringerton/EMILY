# okemily.com Error 525 — diagnosis and founder steps (2026-11-15)

Reported: Cloudflare **525 SSL handshake failed**, 2026-11-15 17:11 UTC (Toronto edge, Ray a5afe02def95375a).
Re-checked 18:19 UTC from the Windows dev box: still 525 (ORD edge, Ray a5b0443caef5f53a).

## In plain words

Cloudflare is fine. The **origin behind it has nothing serving TLS**. Cloudflare can open a TCP
connection to the GKE edge Gateway's address, but the Google load balancer there presents **no
certificate for any hostname** and hangs up. That is exactly a 525. It is not an expired cert or a
strict-mode mismatch. There is no cert, and almost certainly no Gateway or backends behind that IP
any more. The whole GKE footprint looks down, not only okemily.com (see the L4 IP below).

Nothing on this dev box can fix it: there is no `gcloud`, no GKE credentials, no Node/wrangler, and
DNS changes are the founder's call. So this doc gives the evidence and two exact paths.

How these fit together:

- `91-edge-gateway.yaml`: `edge-gw` is a `gke-l7-global-external-managed` Gateway on the reserved global
  address `gateway-edge` with cert map `edge-certs`. `95-okemily-apex.yaml` routes okemily.com and www to it.
  `WOTAN/scripts/deploy-cloudflare-pages.ps1` also records "okemily.com points at the GKE gateway".
- 136.68.242.3 is the address the DNS-only subdomains use for that Gateway. A Google front end that
  still accepts TCP but offers no cert for any SNI usually means one of two things. Either the address
  is still reserved but no forwarding rule or target proxy uses it, or the cert map is gone or empty.
- The L4 IP is dead on every port too, which points at the cluster or project as a whole rather than
  only the cert map. Likely causes are billing or credits (the K8s northstar §7 already flagged the
  credit balance), a deleted or stopped cluster, or deleted Gateway resources. Which one it is can
  only be seen from the GCP console or `gcloud` (step A).
- **Changing the Cloudflare SSL mode will not help.** Full or Flexible would not get a certificate
  that does not exist, and Flexible would try port 80, which this Gateway has no listener for (empty
  reply above). Do not turn TLS off.

## Path A — bring the GKE origin back (restores everything: site, blog, tyler, IDUNA, SSO, games)

On a machine with the Google Cloud SDK, logged in as the project owner:

```bash
gcloud auth login
gcloud config set project project-d24a71e9-2daf-4b2d-917
gcloud billing projects describe project-d24a71e9-2daf-4b2d-917        # billingEnabled must be true
gcloud container clusters list                                          # cluster present? STATUS RUNNING?
gcloud compute addresses list --global --filter="name=gateway-edge"    # expect 136.68.242.3; RESERVED (not IN_USE) = Gateway LB is gone
gcloud certificate-manager maps entries list --map=edge-certs           # needs entries for okemily.com AND *.okemily.com
gcloud certificate-manager certificates list                            # okemily-com-wild: state ACTIVE, not expired
```

Then match the result to the fix:

1. **`billingEnabled: false`, or credits exhausted:** re-attach a billing account in the console
   (Billing → Account management → project-d24a71e9-…). Workloads come back as the cluster
   reschedules them. Re-run the curl below.
2. **Cluster missing or not RUNNING:** this is a rebuild, not a restart. Decide between rebuilding GKE
   and the Vultr move (disputes doc D-4). Path B gives a stopgap meanwhile.
3. **Cluster RUNNING but `gateway-edge` shows RESERVED:**
   `gcloud container clusters get-credentials <cluster> --region us-central1`, then
   `kubectl -n emily get gateway edge-gw -o yaml`. Read `status.conditions` (Accepted/Programmed) for the
   reason. Re-apply `91-edge-gateway.yaml` and `95-okemily-apex.yaml` if the objects are missing.
4. **Cert map empty or missing the apex:** a wildcard `*.okemily.com` does **not** cover the bare
   `okemily.com`. The map needs an entry for `okemily.com` too, with a cert whose SANs include it.

Verify (from anywhere):

```bash
openssl s_client -connect 136.68.242.3:443 -servername okemily.com </dev/null 2>/dev/null | openssl x509 -noout -subject -dates -ext subjectAltName
curl -sSI https://okemily.com/ | head -1      # want HTTP/1.1 200 (or a 30x), not 525
```

## Path B — stopgap: static okemily.com on Cloudflare Pages (minutes, partial)

This brings back the static pages in the `emilyspringerton/OKEMILY` repo **only**. Everything IDUNA
renders or serves stays down until Path A: `/blog`, `/tyler`, `/prompt-o-verse`, `blog-manifest.txt`,
`/battlegrounds`, `/api`, `/admin`, `/portal`, `/nock`, `/q`, `/.well-known/jwks.json` and SSO.
`iam.` and the other subdomains are not covered either.

On the founder's Windows machine (needs Node.js, a download: `winget install OpenJS.NodeJS.LTS`):

```powershell
cd D:\WORKSPACE\MONOREPO\WOTAN
git clone git@github.com:emilyspringerton/OKEMILY.git ..\..\OKEMILY-pages     # or an existing OKEMILY checkout
powershell -ExecutionPolicy Bypass -File scripts\deploy-cloudflare-pages.ps1 -TokenFile <your Cloudflare token file> -Site ..\..\OKEMILY-pages -Project okemily -Domain okemily.com -Zone okemily.com
```

On purpose, the script will **not** overwrite the existing okemily.com record. To cut over:

1. Cloudflare dashboard → okemily.com → **DNS → Records**. Note down, then delete, the record(s) named
   `okemily.com` that point at the GKE gateway (expected 136.68.242.3). Keep a screenshot so you can
   restore them for Path A.
2. **Workers & Pages → okemily → Custom domains → Set up a domain → `okemily.com`**. With the zone on
   Cloudflare, it creates the proxied CNAME to `okemily.pages.dev` itself.
3. Optional: repeat for `www.okemily.com`.
4. Verify: `curl -sSI https://okemily.com/ | head -1` gives a 200.

To undo once GKE is back: remove the Pages custom domain and restore the record(s) from step 1.
